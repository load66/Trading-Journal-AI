# BonusTracker account questions

`POST /api/bonus-tracker/ask` remains owner-only and accepts one question and a bounded list of saved facts. It requires the existing owner authorization check even when the journal middleware is disabled locally. It never queries journal tables, reads uploads, fetches user-supplied URLs, or modifies bonus records. Only the configured Groq connection is used; no fallback sends this context to another provider.

`POST /public/bonus-tracker/ask` is an isolated anonymous route for the BonusTracker browser origin. It consumes only client-supplied facts and uses the same validation, model, cache and total allowance. The origin restriction prevents other browser origins, but is not authentication: non-browser callers can spoof it. Anonymous calls have a separate ceiling of 20 provider attempts per UTC day per server process; failures count. They cannot bypass the shared daily limit or minimum interval. The journal authentication middleware is unchanged.

The frontend answers supported common questions locally from saved rules with no network request. It labels these as saved-rule answers. Other questions and the explicit “Ask AI for more” action use the anonymous route without cookies or owner tokens. The frontend explains the data sharing before sending. It sends one bonus's saved terms, lifecycle dates, task counts, canonical closure checks and calculated dates. Notes, account identifiers, other bonuses, transactions and journal data are excluded. Long identifiers are redacted from fact text. Up to 10,000 characters of historical terms are included, with an explicit truncation marker. Current offers and eligibility are not verified by this feature.

AI returns an explanation, supporting fact IDs, and missing information. IDs must exist in the supplied context; newly invented numeric values are rejected. This validates structural grounding, not every semantic claim. Saved facts remain available for review, and existing financial calculations and closure gates remain authoritative. Answers cannot update accounts, execute actions or produce import JSON. Changed facts invalidate client results and cache identity.

Answers begin with the specific question's answer, followed by its saved conditions. The prompt uses canonical next-action and closure-gate facts, preserves combined versus alternative fee waivers and recurring periods, and treats absent fee wording as unknown. Conflicting or shortened evidence calls for verification. The tracker displays its own closure verdict and next step alongside the explanation; AI cannot authorize closure or override those results.

BonusTracker no longer asks for credentials or manages Supabase sessions. The existing owner-only route and journal authorization remain intact. No Supabase configuration, tables or policies are changed.

Default allowance is 30 attempts per UTC day per server process, configurable from 1 to 100. Failures count. Calls are serialized with a five-second minimum interval. Each call has a 35-second provider timeout, a 2,000-token output cap and no paid automatic retries. Identical question/context answers can be reused in memory for 15 minutes; the cache has at most 30 entries. Inputs are not persisted; responses are held briefly in the process cache. Counters reset when the process restarts, so this is an app guard rather than a provider billing cap.

Tests use synthetic data. They cover authentication before provider access, fail-closed local configuration, input and answer validation, unknown citations, invented numeric values, cache invalidation, budget handling and sanitized errors. Browser tests cover no-login access, local answers without requests, explicit AI sending without credentials, one-account context, cited facts, responsive layout, malformed output, rate limits, local fallback and unchanged saved records. Production provider behavior depends on deployment and available Groq quota. In-memory limits reset on restart and are not a persistent account-wide billing cap; all replicas have their own counters. The current deployment uses one replica.
